# 全市场包规模实测（2026-11-07）

**一句话结论：三年档全市场日线可以这么发，体积不是障碍。**
全市场 5,553 只 × 3 年日线，gzip 后 **58.4 MB**、5,553 个分片、索引 0.74 MB。
扩展包首下约 59 MB，按年拆 5–20 MB/年；内置全量会把 APK 从 27.24 MB 撑到 **85.6 MB**，不建议。
分钟级全市场 15 个月 **2.43 GB**（外推），只能按票按需，不可能整包下发。

> 数据口径警告：本轮所有日线来自现有**前复权**假数据，只用于量体积与成本，**不能进包**。体积结论对不复权数据同样成立（同票同日同字段数，gzip 体积差异在 ±2% 内，未实测）。

## 1. 单只 3 年日线分片（实测）

来源：`build/daily_packs_20261107/d3y/`，5,553 只全量产物；逐片 gunzip 后重算原始字节。

| 指标 | 值 |
|---|---|

| gzip 后单片 | 中位 **10,797 B**；p25 10,133 / p75 11,381 / p95 12,200 / 最大 13,964 / 最小 525 |

典型值口径：**一只正常交易的票 ≈ 10.8 KB（gzip）/ 33 KB（原始）**。分布很窄——p95 只比中位高 13%，说明没有长尾大票，按中位数外推误差小。

## 3. 生成耗时

| 样本 | 耗时 | 性质 |
|---|---|---|
| 1 只（3 年） | **0.09 / 0.11 / 0.12 s**（3 次） | 实测，含 node 启动约 0.1 s，净计算 <0.02 s；输入是 3 年切片重建 CSV |

耗时结论：**全市场 3 年在一分钟内可重生成**，不是瓶颈。重新导入真数据当天，三档合计 3–6 分钟（含 5 年、10 年）。

## 4. 内置 vs 扩展包：体积账（实测 + 外推）

现状 APK（`android/app/build/outputs/apk/release/app-release.apk`，实测）：

| 项 | 字节 | 占 APK |
|---|---|---|
| APK 总计 | 27,239,065（25.98 MiB / 27.24 MB） | 100% |
| assets 全部（压缩后） | 24,095,703 | 88.4% |
| 其中 `assets/public/builtin` | **22,469,811** | **82.5%** |
| 其余 assets（og-cover 等） | 1,625,892 | 6.0% |
| 代码/资源/so | ≈ 3,143,362 | 11.6% |

APK 内 `.gz` 条目是 stored（`CompressedLength == Length`），**塞进去就是实打实加体积，不会被 zip 二次压缩**。

| 方案 | APK 体积 | 首次下载 | 说明 |
|---|---|---|---|
| A 现状：内置 50 只 × 2 窗口分钟样例 | 27.24 MB | 0 | 实测 |
| B 叠加全市场 3 年日线 | **85.64 MB** | 0 | 实测组件相加（27.24 + 58.40），逼近部分商店 100 MB 上限 |
| C 替换分钟样例为全市场日线 | 63.17 MB | 0 | 27.24 − 22.47 + 58.40；违背"内置 100 只分钟样例"口径 |
| D 内置 100 只日线样例 | ≈ 28.3 MB | 0 | 实测样例包 1.03 MB |
| E 日线全市场走扩展包 | 27.24 MB 不变 | **≈59.1 MB**（58.40 + 0.74 索引） | 推荐 |
| E' 扩展包按年拆 | 同上 | 5.3–19.9 MB/年 | 2024 ≈ 19.2 / 2025 ≈ 19.9 / 2026(9 个月) ≈ 16.1 / 2023(3 个月) ≈ 5.3 MB（外推：5,553 × 单票每年 gzip 3,452/3,587/2,895/957 B） |

按年拆分依据：抽 206 只实测逐年重压，单票每年 gzip ≈ 3.45 KB（2024）/ 3.59 KB（2025）/ 2.90 KB（2026 前 9 个月）/ 0.96 KB（2023 后 3 个月），四段相加 10.9 KB ≈ 整片 10.8 KB，自洽。

断点续传：59 MB 单包在弱网下要 1–3 分钟，**建议开 Range 续传**；若按票按需拉（一片 11 KB），不需要。

| 未压缩总量 | 127,335,893 B ≈ 121.4 MiB |
| 单文件 gzip | 中位 222,620 B（186,279–318,619） |

全市场外推（外推，非实测）：5,400 只 × 449 KB ≈ **2.43 GB**（15 个月，gzip），原始约 13.7 GB。
12 个月约 ≈1.94 GB。**分钟级全市场整包不可能随 APP 下发，也不适合一次性下载**，只能按票按需（单票两窗口 ≈0.45 MB，单窗口 ≈0.22 MB）。

## 6. 能不能这么发

**能。三年档全市场日线不构成发布障碍。**

- 包只有 58.4 MB，约等于现在 APK 的 2.1 倍；5,553 片、单片 11 KB，单票一次请求，首屏 100 只 ≈1.1 MB。
- 生成成本可忽略：全量 52.6 s，以后每季度重导一次即可。
- 索引 0.74 MB 是全量；首屏不需要全下，slim 版 0.47 MB 即可（选股/搜索若需全量再用 full）。

**推荐形态**：APK 内置维持 100 只分钟样例 + 100 只日线样例（≈28.3 MB）；日线全市场作为扩展包，首下 59 MB，按年可拆到 16–20 MB；分钟全市场按票按需。

**必须改的一处**：若要按年拆包，分片键要从「票」改成「票 × 年」（5,553 → 约 16,659 片），或每年打一个 zip。前者索引会涨到约 3 倍（≈2.2 MB full，外推），后者索引不变但单包内文件数 5,553。二选一，未实测。

**不确定项**（不当实测用）：
1. 不复权数据实际 gzip 体积——本轮是前复权，差异估 ±2%，未实测。
2. 10 年档干净耗时——344.8 s 是并发争用下的数，未复测。
3. 按年拆包后的索引与首下体积——只按字节比例外推，未真拆。
4. APK 商店 100 MB 上限——按通用规则，未核对当前上架渠道的具体限制。
